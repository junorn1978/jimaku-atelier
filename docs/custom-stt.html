字幕アトリエ ／ 上級者向け

音声認識サーバー接続仕様rtl-stt/1

字幕アトリエの音声認識を、ブラウザの Web Speech API ではなく自分で用意したサーバー（Whisper など）に 任せるための接続仕様です。言語タブの［上級者向け］で「音声認識サーバー」をオンにし、サーバーの URL を入れると使えます。

役割分担 接続 クライアント → サーバー サーバー → クライアント やりとりの例 注意 サンプル

役割分担

字幕アトリエがやること

  • 選んだマイクの音声を 16kHz・モノラル・16bit PCM にして送り続ける
  • 話者の「間」を検出して知らせる（使うかどうかはサーバー次第）
  • 返ってきた認識結果を原文の字幕に出し、翻訳して翻訳字幕に出す（翻訳もサーバーが返せば、それをそのまま使う）

サーバーがやること

  • 音声を受け取り、認識結果を返す
  • 必要なら言語の判定や翻訳もして返す
  • どのモデルを使うか、どこで文を区切るか、途中経過を出すかはサーバーが決める

必須なのは final の text だけです。ほかの項目はすべて任意で、 字幕アトリエは受け取ったものに合わせて動きます。

接続

  • WebSocket 1 本です。URL は ws:// か wss://。
  • ブラウザの WebSocket はヘッダーを付けられないので、認証が要るなら URL のクエリ （例：ws://127.0.0.1:9000/stt?token=xxxx）で受け取ってください。
  • 接続は［開始］を押したときに張り、［停止］で閉じます。途中で切れた場合、字幕アトリエは 2 秒おきに張り直します（切れていた間の音声は捨てます）。

オンライン版（GitHub Pages, https）から ws://localhost ／ ws://127.0.0.1 へは そのままつながります（初回だけブラウザがローカルネットワークへのアクセス許可を求めます）。

LAN 上の別の PC に ws:// でつなぐ場合、https のページからは混在コンテンツとして ブロックされることがあります。そのときはローカル版（launch_chrome.bat）を使うか、 サーバーを wss:// にしてください。

メッセージ

テキストフレームは JSON、バイナリフレームは音声です。知らない type は無視してください（今後の追加のため）。

クライアント → サーバー

config

→ サーバー テキスト

接続直後に必ず 1 回送ります。開始後に翻訳言語が変わったときにも、その時点の内容で送り直します。

{
  "type": "config",
  "protocol": "rtl-stt/1",
  "sourceLang": "ja",
  "sourceLocale": "ja-JP",
  "targetLangs": ["zh-TW", "en"],
  "sampleRate": 16000,
  "format": "pcm_s16le"
}
フィールド内容
sourceLang認識する言語。翻訳用の言語コード（ja、en、zh-TW など。翻訳サーバーの /translate と同じもの）
sourceLocale同じ言語の地域付きの ID（ja-JP、en-US、zh-HK、yue-Hant-HK など）。香港の書き言葉と広東語の区別などはこちらで
targetLangs翻訳先。翻訳しない枠は含まれないので 0〜2 個。順番が final.translations の順番になる
sampleRate ／ format音声の形式。現行は常に 16000 ／ pcm_s16le

音声

→ サーバー バイナリ

16kHz・モノラル・符号付き 16bit リトルエンディアンの PCM。ヘッダーなしの生データです。 約 100ms（3200 バイト）ずつ、停止するまで途切れずに送ります。無音の間も送ります。

ブラウザ側のエコーキャンセル・ノイズ抑制・自動ゲインはすべて切ってあります。

pause

→ サーバー テキスト 
{ "type": "pause" }

話者が 0.35 秒以上黙ったときに 1 回送ります（次に話し始めるまで繰り返しません）。 BGM を除いた音量で判定しているので、音楽が流れていても間は取れます。

Whisper のように 1 文ずつ処理するモデルなら、「前の pause から今回の pause までの音声」を 1 文として認識するのがいちばん簡単です。自分で VAD をかけるサーバーは無視して構いません。 ただし話し続けて間がない話者もいるので、どちらにしても 1 文の長さの上限（10 秒前後）はサーバー側で決めてください。

stop

→ サーバー テキスト 
{ "type": "stop" }

停止ボタンが押されました。送った直後に接続を閉じます。停止すると字幕は消えるので、 処理中の結果を返す必要はありません。

サーバー → クライアント

ready

← クライアント 任意 
{ "type": "ready" }

モデルの読み込みなどが済んで受け付けられるようになったら送ってください。送らなくても動きます （設定画面の状態表示が「準備完了」になるだけです）。

partial

← クライアント 任意 
{ "type": "partial", "text": "今日はいい天" }

認識途中の文。原文の字幕に「認識中」として表示されます。差分ではなく、その文の今の全文を送ってください。 途中経過を出せないモデルなら送る必要はありません。

final

← クライアント 必須 
{ "type": "final", "text": "今日はいい天気ですね。", "translations": ["今天天氣真好呢。", "Nice weather today."] }
{ "type": "final", "text": "Thank you so much!", "lang": "en" }

1 文の確定。原文の字幕を確定表示にし、翻訳に回します。

フィールド内容
text確定した文（必須）
translations 任意。付けないと、字幕アトリエが選んでいる翻訳エンジン（Google 翻訳、ブラウザ翻訳、翻訳サーバー）で翻訳します。 付けると翻訳エンジンは使わず、それをそのまま翻訳字幕に出します。 順番は直前の config の targetLangs と同じにしてください。
lang 任意。この文の言語で、サーバーが文ごとに言語を判定する場合に付けます。 config の sourceLang と同じ形のコード（en、ja、zh-TW など）です。 zh のような地域なしのコードでも構いません（どの中国語か決められないときは翻訳エンジンの自動判定に任せます）。 字幕アトリエはこの言語を原文として翻訳エンジンに渡します。付けなければ config の言語のままです。 translations を付ける場合は使いません。

final の後は、次の partial が来るまで認識途中の文はないものとして扱います。

error

← クライアント 任意 
{ "type": "error", "message": "model not loaded" }

設定画面の状態表示に出します。接続は切りません。続けられない場合はサーバーから閉じてください。

やりとりの例

  1. →config
  2. ←ready
  3. →音声 3200 bytes × n
  4. ←partial 「今日は」 （任意）
  5. →pause
  6. ←final 「今日はいい天気ですね。」
  7. →音声 …
  8. →stop （接続を閉じる）

→ 字幕アトリエ → サーバー ← サーバー → 字幕アトリエ

注意

  • Whisper は無音や BGM だけの区間で「ご視聴ありがとうございました」のような文を作ることがあります。 音量の低い区間は認識しない、no_speech_prob の高い結果は捨てる、などはサーバー側で対策してください。 字幕アトリエのフィルター（置換・ブラックリスト）は partial ／ final の両方にかかります。
  • 字幕の表示時間などは、ブラウザの音声認識のときと同じ設定がそのまま効きます。
  • 音声認識サーバーを使っている間、マイク設定の「文の区切り」は使われません。

サンプル

リポジトリの docs/custom-stt-sample/ に、動かせるサーバーが 3 つあります。

ファイル内容
echo_server.pyモデルなし。受け取った音声の長さを返すだけで、接続の確認用です。--translate で仮の翻訳も返します。
whisper_server.pyfaster-whisper を使う最小のサーバー。pause ごとに 1 文として認識します。
soniox_server.pyクラウドの Soniox に音声を中継するサーバー。文の区切りは Soniox が決めるので pause は使いません。API キーはこのサーバー側に置きます。
 
pip install websockets faster-whisper numpy
# NVIDIA GPU を使う場合（Windows）
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12

python whisper_server.py --model large-v3-turbo --device cuda --compute-type int8_float16

--detect ja,en,zh のように付けると、文ごとにその中から言語を判定して final.lang を返します。 候補を絞ると、「はい」「OK」のような短い文でも判定を外しにくくなります。 

pip install websockets
$env:SONIOX_API_KEY = "..."   # PowerShell

python soniox_server.py --detect ja,en

Soniox は接続している時間で課金されます。字幕アトリエは開始している間、無音も含めて音声を送り続けるので、 開始から停止までがそのまま課金対象です。--detect は whisper_server.py と同じ意味です。
