# カスタム STT 接続仕様（rtl-stt/1）

字幕アトリエの音声認識を、ブラウザの Web Speech API ではなく自分で用意したサーバー
（Whisper など）に任せるための接続仕様です。言語タブの［上級者向け］で「音声認識サーバー」を
オンにし、サーバーの URL を入れると使えます。

字幕アトリエ側がやること：

- マイク（選んだデバイス）の音声を 16kHz・モノラル・16bit PCM にして送り続ける
- 話者の「間」を検出して知らせる（使うかどうかはサーバー次第）
- 返ってきた認識結果を原文の字幕に出し、翻訳して翻訳字幕に出す
  （翻訳もサーバーが返せば、それをそのまま使う）

サーバー側がやること：音声を受け取り、認識結果（と、必要なら翻訳）を返す。
どのモデルを使うか、どこで文を区切るか、途中経過を出すかはサーバーが決めます。

## 接続

- WebSocket 1 本です。URL は `ws://` か `wss://`。
- ブラウザの WebSocket はヘッダーを付けられないので、認証が要るなら URL のクエリ
  （例：`ws://127.0.0.1:9000/stt?token=xxxx`）で受け取ってください。
- 接続は［開始］を押したときに張り、［停止］で閉じます。途中で切れた場合、字幕アトリエは
  2 秒おきに張り直します（切れていた間の音声は捨てます）。
- オンライン版（GitHub Pages, https）から `ws://localhost` / `ws://127.0.0.1` へはそのまま
  つながります（初回だけブラウザがローカルネットワークへのアクセス許可を求めます）。
  LAN 上の別の PC に `ws://` でつなぐ場合、https のページからは混在コンテンツとして
  ブロックされることがあります。そのときはローカル版（`launch_chrome.bat`）を使うか、
  サーバーを `wss://` にしてください。

## メッセージ

テキストフレームは JSON、バイナリフレームは音声です。知らない `type` は無視してください
（今後の追加のため）。

### クライアント → サーバー

#### `config`（テキスト）

接続直後に必ず 1 回送ります。開始後に翻訳言語が変わったときにも、その時点の内容で送り直します。

```json
{
  "type": "config",
  "protocol": "rtl-stt/1",
  "sourceLang": "ja",
  "sourceLocale": "ja-JP",
  "targetLangs": ["zh-TW", "en"],
  "sampleRate": 16000,
  "format": "pcm_s16le"
}
```

| フィールド | 内容 |
|---|---|
| `sourceLang` | 認識する言語。翻訳用の言語コード（`ja`、`en`、`zh-TW` など。カスタム URL 翻訳の `/translate` と同じもの） |
| `sourceLocale` | 同じ言語の地域付きの ID（`ja-JP`、`en-US`、`zh-HK`、`yue-Hant-HK` など）。香港の書き言葉と広東語の区別などはこちらで |
| `targetLangs` | 翻訳先。翻訳しない枠は含まれないので 0〜2 個。順番が `final.translations` の順番になる |
| `sampleRate` / `format` | 音声の形式。現行は常に 16000 / `pcm_s16le` |

#### 音声（バイナリ）

16kHz・モノラル・符号付き 16bit リトルエンディアンの PCM。ヘッダーなしの生データです。
約 100ms（3200 バイト）ずつ、停止するまで途切れずに送ります。無音の間も送ります。

ブラウザ側のエコーキャンセル・ノイズ抑制・自動ゲインはすべて切ってあります。

#### `pause`（テキスト）

```json
{ "type": "pause" }
```

話者が 0.35 秒以上黙ったときに 1 回送ります（次に話し始めるまで繰り返しません）。
BGM を除いた音量で判定しているので、音楽が流れていても間は取れます。

Whisper のように 1 文ずつ処理するモデルなら、「前の `pause` から今回の `pause` までの音声」を
1 文として認識するのがいちばん簡単です。自分で VAD をかけるサーバーは無視して構いません。
ただし話し続けて間がない話者もいるので、どちらにしても 1 文の長さの上限（10 秒前後）は
サーバー側で決めてください。

#### `stop`（テキスト）

```json
{ "type": "stop" }
```

停止ボタンが押されました。送った直後に接続を閉じます。停止すると字幕は消えるので、
処理中の結果を返す必要はありません。

### サーバー → クライアント

#### `ready`（任意）

```json
{ "type": "ready" }
```

モデルの読み込みなどが済んで受け付けられるようになったら送ってください。送らなくても動きます
（設定画面の状態表示が「接続済み」になるタイミングが変わるだけです）。

#### `partial`（任意）

```json
{ "type": "partial", "text": "今日はいい天" }
```

認識途中の文。原文の字幕に「認識中」として表示されます。差分ではなく、その文の
**今の全文**を送ってください。途中経過を出せないモデルなら送る必要はありません。

#### `final`

```json
{ "type": "final", "text": "今日はいい天気ですね。", "translations": ["今天天氣真好呢。", "Nice weather today."] }
{ "type": "final", "text": "Thank you so much!", "lang": "en" }
```

1 文の確定。原文の字幕を確定表示にし、翻訳に回します。

- `translations` を**付けない**と、字幕アトリエが言語タブで選んでいる翻訳エンジン
  （Google 翻訳、ブラウザ翻訳、カスタム URL）で翻訳します。
- `translations` を**付ける**と翻訳エンジンは使わず、それをそのまま翻訳字幕に出します。
  順番は直前の `config` の `targetLangs` と同じにしてください。
- `lang`（任意）：この文の言語。サーバーが文ごとに言語を判定する場合に付けます。
  `config` の `sourceLang` と同じ形のコード（`en`、`ja`、`zh-TW` など）で、`zh` のような
  地域なしのコードでも構いません（字幕アトリエが使っている言語の中から合うものを選びます）。
  字幕アトリエはこの言語を原文として翻訳エンジンに渡します。付けなければ `config` の言語のままです。
  `translations` を付ける場合は使いません。
- `final` の後は、次の `partial` が来るまで認識途中の文はないものとして扱います。

#### `error`（任意）

```json
{ "type": "error", "message": "model not loaded" }
```

設定画面の状態表示に出します。接続は切りません。続けられない場合はサーバーから閉じてください。

## 最小のやりとり

```
→ {"type":"config","protocol":"rtl-stt/1","sourceLang":"ja",...}
← {"type":"ready"}
→ [PCM 3200 bytes] [PCM 3200 bytes] ...
← {"type":"partial","text":"今日は"}          （任意）
→ {"type":"pause"}
← {"type":"final","text":"今日はいい天気ですね。"}
→ [PCM ...] ...
→ {"type":"stop"}   （接続を閉じる）
```

## 注意

- Whisper は無音や BGM だけの区間で「ご視聴ありがとうございました」のような文を作ることがあります。
  音量の低い区間は認識しない、`no_speech_prob` の高い結果は捨てる、などはサーバー側で対策してください。
  字幕アトリエのフィルター（置換・ブラックリスト）は `partial` / `final` の両方にかかります。
- 字幕の表示時間などは Web Speech のときと同じ設定がそのまま効きます。

## サンプル

`docs/custom-stt-sample/` に、faster-whisper を使う最小のサーバーと、
モデルなしで動作確認だけできるエコーサーバーがあります。
faster-whisper のサーバーは `--detect ja,en,zh` のように付けると、文ごとにその中から言語を判定して
`final.lang` を返します。
